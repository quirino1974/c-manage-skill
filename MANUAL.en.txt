manage-skill: user manual
=========================
Author: Quirino Scaramastra

manage-skill exports, catalogs and describes Claude skills, and moves them between accounts while managing API keys. You use it from the command line (ms) or from the Qt window (manage-skill-qt).

Copyright (C) 2026 Quirino Scaramastra. manage-skill is free software, distributed under the GNU General Public License version 3 or later (GPL-3.0-or-later), with no warranty. The license text is in the LICENSE file; copyright and third-party components are in the COPYRIGHT file. From the terminal: ms --versione; from the window: the About button.

Language. The program is written in Italian, so the commands and options keep their Italian names: ms catalogo, ms esporta, --prova and so on. Messages, help and the window can be shown in English: see §10.1.

1. Installation
---------------

    cd manage-skill      # the repository folder
    ./installa.sh

The script does three things:
- creates the Python environment .venv;
- installs the anthropic SDK;
- creates the ms command in ~/.local/bin.

From then on ms works from any folder. Alternatively, use ./ms from the program folder.

Help: ms --help and ms <command> --help. Version: ms --versione.

2. Folders
----------

  Folder                           Contents
  ------------------------------   ------------------------------------------------------------------------------------------
  manageskill/                     the Python program; motore.py and servizi.py serve the Qt window
  manageskill/lingue/              translations (en.json)
  gui-qt/                          the C++ Qt window and the compila.sh script
  dati/config.json                 optional settings (see §11)
  dati/account.json                account registry, without keys
  dati/categorie.json              category rules and manual assignments
  catalogo/                        catalogo.html and catalogo.json, regenerated by every ms catalogo
  manageskill/archivio/            all exports: single skills (ms esporta), backup copies, _da-caricare/ (ZIPs for claude.ai)
  manageskill/archivio/cloud/      exports of the claude.ai account skills (ms cloud esporta)
  manageskill/terze-parti/         installed third-party skills (§16)
  ~/.config/manage-skill/chiavi/   keys saved to file (only if you choose file), outside the project

3. Where skills are read from (sources)
---------------------------------------

Only your skills. To avoid ownership problems, the program shows and exports only the skills you created (plus the third-party skills you add yourself, with their license). Anthropic's skills on claude.ai and the skills of marketplace plugins are not read. The setting is "solo_utente": true in dati/config.json (default); setting it to false restores the full view, at your own responsibility.

  Source        Where                                                                      Editable
  -----------   ------------------------------------------------------------------------   --------
  claude-code   ~/.claude/skills/<name> (including links to projects)                      yes
  progetto      <project>/.claude/skills/<name> under the radici_progetti folders (§11)    yes
  plugin        ~/.claude/plugins/**/skills/<name> (read only with "solo_utente": false)   no
  claude-ai     ~/.claude/skills/synced/<account>/, the copy synced by Claude Code         no
  terze-parti   manageskill/terze-parti/<name>                                             yes
  archivio      manageskill/archivio/<name>/<date>/<name>                                  no

The origin says who created the skill:
- tua (yours): your skills;
- anthropic: Anthropic's skills;
- plugin: plugin skills;
- terze parti: third-party skills.

When a skill is in several sources and you do not give --da, the program picks the copy in this order: claude-code, progetto, claude-ai, terze-parti, archivio, plugin.

4. Catalog and description
--------------------------

ms catalogo
~~~~~~~~~~~
Lists all skills with category, activation state (ACTIVE column), sources, number of files, size and copy status:
- ok: all copies are identical;
- DIVERSE (DIFFERENT): at least two copies differ.

Each run saves catalogo/catalogo.html and catalogo/catalogo.json.

  Option                           Effect
  ------------------------------   ----------------------------------------------
  --fonte claude-code progetto …   only these sources
  --categoria social               only one category (part of the name is enough)
  --mie                            only your skills
  --json                           print the catalog as JSON
  --apri                           open the HTML catalog in the browser

Active or disabled
~~~~~~~~~~~~~~~~~~
The ACTIVE column (in the window: Active, and Activation in the copies panel) says whether Claude uses the skill:

  Value                                 Meaning
  -----------------------------------   -------------------------------------------------------------------------------------------------------------------------------------------------------
  attiva (active)                       Claude Code loads it and can use it on its own
  solo manuale (manual only)            used only when invoked with /name (skillOverrides: "user-invocable-only" or disable-model-invocation: true in the frontmatter)
  attiva (compatta) (active, compact)   active, but Claude only sees its name (skillOverrides: "name-only")
  disattivata (disabled)                turned off with skillOverrides: "off" in the Claude Code settings
  su claude.ai (on claude.ai)           the skill is only on claude.ai: the on/off switch is visible only on the website (Settings > Capabilities > Skills); the synced copy does not record it
  non caricata (not loaded)             a manage-skill copy (archive, third parties): Claude does not use it from there

For Claude Code the program reads skillOverrides in ~/.claude/settings.json and, for project skills, in <project>/.claude/settings.json and settings.local.json. Hovering over the cell shows the reason.

ms descrivi <name> [--da SOURCE]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Shows the full details:
- category and origin;
- folder and fingerprint;
- frontmatter, description and file list;
- all copies;
- the result of the Skills API validation and of the secret check.

ms confronta <name>
~~~~~~~~~~~~~~~~~~~
Compares all copies of the skill file by file:
- + file only in the second copy;
- - file only in the first;
- ~ file with different content.

ms valida <skill> [--da SOURCE]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Checks the Skills API rules:
- name present, lowercase letters, digits and hyphens only, at most 64 characters, without the words "anthropic" or "claude";
- description present, at most 1024 characters;
- no XML tags;
- size at most 30 MB.

<skill> can be a name, a folder or a ZIP.

ms segreti <skill> or ms segreti --tutte
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Looks for API keys (Anthropic, AWS, GitHub, Slack), private keys, plain-text passwords and tokens, and sensitive files (.env, .netrc, id_rsa, …). It shows the file and the line, never the value. With --tutte it checks all Claude Code and project skills.

Categories
~~~~~~~~~~
The rules are in dati/categorie.json, created on first use.

How they work:
- each word found in the name is worth 3 points, in the description 1 point;
- words are matched whole, so "post" does not match "posta";
- with a trailing asterisk a word becomes a stem: certificaz*.

To pin a skill's category by hand:

    "assegnate": { "my-skill": "Finanza" }

5. Cloud skills (claude.ai account)
-----------------------------------

With "solo_utente": true (default) only your skills appear and are exported here: the --tutte options do not add Anthropic's.

claude.ai has no public API to download skills. Claude Code, however, keeps a synced copy on the PC, and manage-skill works on that. The sync date appears in every listing: for the latest version, open Claude Code before exporting.

ms cloud elenco [--mie] [--json] [--api]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Shows for each skill:
- the type: tua (yours), Anthropic, esempio Anthropic (Anthropic example);
- the category;
- the update date on claude.ai;
- files and size;
- the comparison with the local Claude Code copy: uguale (same), diversa (different), assente (missing).

With --api it adds the metadata of the skills in the registered API accounts: name, id, version. Files are not included, because the API does not provide them.

ms cloud esporta
~~~~~~~~~~~~~~~~
Exports on request into the program subfolder manageskill/archivio/cloud/:

    ms cloud esporta --mie                    # all yours
    ms cloud esporta other-skill     # only some, by name

Each export creates:

    manageskill/archivio/cloud/claude-ai_<org>_<user>/<YYYY-MM-DD_HHMMSS>/
      skill/<name>/      the complete skill folder
      zip/<name>.zip     ready to upload again to claude.ai or to the Skills API
      indice.json        claude.ai id, type, fingerprint, new/same/changed, API issues, secrets
      indice.html        the export catalog, to open in the browser
    manageskill/archivio/cloud/claude-ai_…/ultima  ->  link to the most recent export

At the end the command lists the skills that are new or changed since the previous export.

A skill with possible secrets is skipped and reported, while the others are exported anyway. If the warning is a false alarm, run again with --ignora-segreti.

ms cloud verso-api <account> [skill…] [--prova] [--forza] [--tutte] [--ignora-segreti]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Automatically imports the claude.ai skills into a Claude Console API account:
- a skill missing from the account is created;
- a skill already there and changed since manage-skill last uploaded it becomes a new version;
- an identical skill is skipped ("already up to date"). With --forza it is uploaded again anyway.

Without names it takes all your skills. Skills with possible secrets or that break the Skills API rules are skipped and reported.

The command also warns when the PC has a more recent version than claude.ai: in that case consider updating claude.ai first, or use ms importa <name> --verso <account>, which uploads the PC copy.

What has been uploaded is recorded in dati/sincronizzazioni.json, without keys. That is how the program knows what has changed.

    ms cloud verso-api work-api --prova     # what it would do
    ms cloud verso-api work-api             # do it

In the Qt window: claude.ai cloud tab, row "Import into an API account". The button acts on the selected skills, or on all yours if none is selected. "dry run" is on by default.

ms cloud storico
~~~~~~~~~~~~~~~~
Lists the exports in manageskill/archivio/cloud/ with:
- date;
- number of skills;
- how many changed and how many were skipped;
- sync date.

6. Export to the archive
------------------------

ms esporta <skill…> | --mie | --tutte [--da SOURCE] [--ignora-segreti]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Creates manageskill/archivio/<name>/<date-time>/ with:
- the skill folder;
- <name>.zip;
- skill.json, with source, fingerprint, files, API issues and the secret check result.

It stops if it finds possible secrets.

Examples:

    ms esporta my-skill
    ms esporta --mie
    ms esporta other-skill --da claude-ai

7. Import into an account
-------------------------

ms importa <skill…> --verso ACCOUNT [options]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
<skill> can be one of:
- a name;
- a folder with SKILL.md;
- a ZIP;
- an archive folder (the one with skill.json).

  Account type   What it does
  ------------   ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  api            validates the skill, then creates it with the Skills API. If a skill with the same name exists, it creates a new version
  claude-code    copies the folder. If the skill is already there and identical it says "already identical". If it differs it stops: with --sovrascrivi it first archives the current copy, then replaces it. It never writes inside a link: in that case update the skill in the project
  claude-ai      prepares the ZIP in the account folder or in manageskill/archivio/_da-caricare/<account>/. You upload it from claude.ai, Settings > Capabilities > Skills > Upload skill

  Option             Effect
  ----------------   ------------------------------------------------
  --prova            show what it would do, without changing anything
  --sovrascrivi      claude-code only, see above
  --da SOURCE        which copy to take the skill from
  --mie, --tutte     import all your skills
  --ignora-segreti   proceed even with secret check warnings

Examples:

    ms importa my-skill --verso work-api --prova
    ms importa my-skill --verso work-api
    ms importa manageskill/archivio/cloud/claude-ai_…/ultima/zip/other-skill.zip --verso locale --sovrascrivi
    ms importa --mie --verso other-pc        # claude-code account with --cartella on a shared disk

8. Accounts and keys
--------------------

ms account elenco
~~~~~~~~~~~~~~~~~
Lists the accounts. locale is predefined and points to ~/.claude/skills.

ms account aggiungi <name> --tipo api|claude-code|claude-ai [options]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

    ms account aggiungi work-api --tipo api                  # asks for the key and saves it in the keyring
    ms account aggiungi work-api --tipo api --chiave file    # or in ~/.config/manage-skill/chiavi (600)
    ms account aggiungi ci --tipo api --chiave env:ANTHROPIC_API_KEY
    ms account aggiungi profile --tipo api --chiave ant      # uses the ant CLI profile
    ms account aggiungi project-x --tipo claude-code --cartella ~/projects/x/.claude/skills
    ms account aggiungi web-work --tipo claude-ai --cartella ~/Downloads/work-skills

Options for api accounts:
- --workspace ID: organization workspace;
- --base-url URL: alternative endpoint;
- --nota: free text.

--sostituisci redefines an existing account.

ms account console [name] [--workspace ID] [--dove keyring|file] [--sostituisci]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Safely sets up a Claude Console API account. The default name is console.

1. On platform.claude.com create an API key under Settings > API keys, in the workspace to read. Do not use an Admin key (sk-ant-admin…): it is rejected.
2. Run the command and paste the key when asked. The key is not shown.
3. The program tests the key right away against the Skills API and saves account and key only if it works.
4. If the key is not tied to a single workspace, give --workspace wrkspc_… (Console > Settings > Workspaces).

The same is done from the Qt window: claude.ai cloud tab > Set up API account (Claude Console). The window's "New account" dialog also tests the key before saving it.

Console skills and claude.ai skills are separate stores. A skill uploaded to claude.ai does not appear in the Skills API and vice versa: the scan tells you where skills with the same name exist.

ms account chiave <name> [--dove keyring|file]
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Enters or replaces the key. It is typed without echo and never appears on screen.

ms account prova <name>
~~~~~~~~~~~~~~~~~~~~~~~
Checks the account:
- for an api account it checks the key and counts the skills, showing only the start and end of the key;
- for the others it checks the folder.

Errors are explained plainly, for example "invalid or revoked API key (401)" or "no Skills API permission (403)".

ms account rimuovi <name>
~~~~~~~~~~~~~~~~~~~~~~~~~
Removes the account and deletes its key from the keyring or the file.

Key rules
~~~~~~~~~
- Keys never go into dati/account.json, archives or exports.
- The keyring is the recommended choice. Use the file only if secret-tool is not available; in that case the program refuses the file if other users can read it.

9. Skills in API accounts
-------------------------

  Command                                     Effect
  -----------------------------------------   -----------------------------------------------------------------------------
  ms remoto elenco <account> [--tutte]        custom skills (with --tutte also Anthropic's): name, id, version, date
  ms remoto versioni <account> <name>         versions of a skill
  ms remoto elimina <account> <name> [--si]   deletes the skill and all its versions. Asks you to type SI. Cannot be undone

10. Management interface (Qt window)
------------------------------------

A native window written in C++ with Qt 6 (folder gui-qt/). There is no server and no open port: each button briefly starts the Python engine (python -m manageskill.motore), passes it the request on standard input and reads the JSON reply. When you close the window nothing keeps running.

Build, once (and after every change to the C++ code):

    sudo apt install qt6-base-dev cmake
    gui-qt/compila.sh            # creates gui-qt/build/manage-skill-qt and the manage-skill-qt command
    manage-skill-qt

compila.sh also installs the icon and the manage-skill entry in the applications menu: search for "manage-skill" in the GNOME overview.

The look follows the system light or dark theme. To choose it by hand: MANAGE_SKILL_TEMA=scuro manage-skill-qt (dark) or chiaro (light). The top bar shows the counters (total skills, yours, to align, third-party), the language menu and the About button, with version, copyright and license.

The window looks for the Python program in the folder where it was built. If you move manage-skill, rebuild or set MANAGE_SKILL_DIR.

It has five tabs (Catalog, claude.ai cloud, Third parties, Accounts and keys, Exports) and an activity log at the bottom.

- Catalog:
  - table of all skills, sortable, with search and filters: category, source, mine only, differing copies only;
  - the Active column shows the activation state (see §4);
  - when a skill's copies differ, the Status column says "copies differ (N)" and Most recent shows ★, the source and the date of the newest version;
  - selecting a skill, the panel below lists all its copies from the most recent, with source, date, status (★ most recent, same, older and different), activation and folder. "Open the copy's folder" opens it in the file manager. For claude.ai copies the cloud update date counts, not the local sync date;
  - next to the copies is the Skill notes box: write and press "Save note" (see §14). The catalog Notes column shows its first line;
  - Edit…, or double-clicking a copy, opens the skill editor (see §15);
  - double-clicking a skill opens its details with description, copies, files, validation, secrets, the SKILL.md text and the button to compare copies;
  - with the checkboxes in the Name column you pick the skills to work on; the bottom bar exports to the archive or imports into an account;
  - dry run is on by default: turn it off to really import, and the window asks for confirmation.
- claude.ai cloud:
  - account skills with type, date, comparison with the local copy and id;
  - buttons to export the selected skills, all yours or all;
  - at the end it offers to open the export index;
  - at the bottom, Set up API account (Claude Console)… guides the account creation, then Scan API account skills lists the skills of all API accounts, with id, version, dates and whether a skill with the same name exists on this PC or on claude.ai.
- Third parties: see §16.
- Accounts and keys:
  - account list, with New account, Test, Change key and Remove (which asks for confirmation);
  - the key is typed in a password field;
  - listing and deleting the skills of an API account: to delete, type the skill name.
- Exports: shows where exports are kept (manageskill/archivio/ and manageskill/archivio/cloud/) and the "Open archive" button. It lists the exports with buttons to open the index or the folder.

Key safety: the key travels from the window to the engine only through standard input, so it is not visible among processes with ps. The engine saves it in the keyring or the protected file and never sends it back.

10.1 Language
-------------

The interface is in Italian or English:
- window: language menu in the top bar (🇮🇹 Italiano / 🇬🇧 English). The choice is remembered and the window is rebuilt at once in the new language;
- command line: MANAGE_SKILL_LINGUA=en ms … or "lingua": "en" in dati/config.json.

Translations are in manageskill/lingue/en.json, a single dictionary for window, engine and command line, generated by strumenti/crea_dizionario_en.py. To fix or add a translation, edit the script and run it again. Command and option names (ms catalogo, --prova…) stay the same in every language. The English documents are MANUAL.en.txt, RELEASENOTES.en.txt and the English part of COPYRIGHT.

11. Settings (dati/config.json, optional)
-----------------------------------------

    {
      "radici_progetti": ["/home/user/projects", "/home/user/Documents/GitHub"],
      "escludi": ["node_modules", ".git", ".venv", "venv", "__pycache__", "data", "archivio"],
      "limite_mb": 30,
      "solo_utente": true,
      "lingua": "en"
    }

- radici_progetti: where to look for .claude/skills folders; without dati/config.json the default is ~/claudeworkspace;
- escludi: folders not to explore;
- limite_mb: maximum size for the Skills API;
- solo_utente: show only your skills (see §3);
- lingua: it or en for the command line.

12. Typical workflows
---------------------

Backup of the cloud skills. Open Claude Code, then:

    ms cloud esporta --mie && ms cloud storico

Align claude.ai and the PC.
1. ms cloud elenco --mie: look at the skills marked diversa (different).
2. ms confronta <name> to see the differences.
3. To upload the local version to claude.ai: ms importa <name> --verso <claude-ai account>, then upload the ZIP from Settings.

Bring your skills into an API organization.
1. ms account console org (asks for the key and tests it).
2. ms importa --mie --verso org --prova.
3. If the result looks right, repeat without --prova.
4. Check with ms remoto elenco org.

13. Common problems
-------------------

  Message                                     What to do
  -----------------------------------------   --------------------------------------------------------------------------------------------------------------
  No claude.ai skills found                   open Claude Code signed in to the claude.ai account, so it syncs the copy
  Possible secrets …                          remove the key from the skill (an environment variable is better); if it is a false alarm use --ignora-segreti
  invalid or revoked API key (401)            ms account chiave <name>
  the key is not tied to a workspace…         give the Workspace ID (--workspace wrkspc_…), or create a key inside the workspace
  … already exists … with different content   ms confronta <name>, then --sovrascrivi if you want to replace it
  … is a link to …                            the skill lives in a project: edit it there
  Non trovo manage-skill in … (window)        rebuild with gui-qt/compila.sh or set MANAGE_SKILL_DIR
  Manca l'ambiente Python … (window)          run ./installa.sh in the program folder

14. Skill notes
---------------

Each skill can have your own note: what it is for, where it comes from, what to remember. The note belongs to the name, so to all copies of the skill. It is kept in dati/note.json and never goes into exports or accounts.

- Window: Catalog tab, select the skill, write in the Skill notes box and press Save note. Emptying the text and saving deletes the note.
- Terminal: ms nota <skill> reads it, ms nota <skill> note text writes it, ms nota <skill> --cancella deletes it.

15. Editing skills
------------------

From the window you edit a skill's files: SKILL.md, references, scripts.

1. In the Catalog select the skill, choose the copy in the copies panel and press Edit…, or double-click the copy. Third-party skills have an Edit… button in their tab.
2. The file list is on the left, the text on the right. New file… adds a file, for example references/examples.md.
3. Save (or Ctrl+S).

Safety rules:
- only claude-code, project and third-party copies can be edited. claude.ai, plugin and archive copies open read-only. To change a claude.ai skill, edit the local copy and upload it again;
- before every save the whole skill is copied to manageskill/archivio/<name>/<date-time>/;
- if another program changed the file after it was opened, the save is refused: reopen the file;
- after saving, the skill is checked again (Skills API rules, name matching the folder, possible secrets) and warnings appear at once;
- the editor accepts only UTF-8 text files up to 1 MB and never writes outside the skill folder;
- if the claude-code copy is a link to a project, the project file, i.e. the original, is edited.

16. Third-party skills
----------------------

Skills written by others, taken from a Git repository, a ZIP (file or https address) or a folder. manage-skill keeps them in manageskill/terze-parti/<name>/, remembers where they come from (dati/terze_parti.json), updates them from the source and syncs them to the accounts you choose. Each skill keeps the license of its source: check it before redistributing.

From the window, Third parties tab:
1. Add…: paste the source (for example https://github.com/anthropics/skills) or choose a folder or a ZIP, and press Find skills. The list shows the number of files, scripts and possible secrets. Tick the skills to add and the accounts to sync them to, then press Add selected.
2. Update from source: downloads the selected skills, or all, again and replaces those that changed. The old version goes to the archive. If you modified a skill here, the update stops; with force it replaces it anyway.
3. Destinations…: chooses the accounts to sync the selected skill to.
4. Sync with accounts brings the skills into their destination accounts:
   - claude-code: copies the skill. If the copy in the account was modified by hand after the last sync, it stops; with force it replaces it, after archiving it;
   - api: creates the skill or a new version, only if the content changed;
   - claude-ai: prepares the ZIP to upload.

   "dry run" is on by default.
5. Edit…, Open folder and Remove. Removing archives the folder and does not touch the copies already synced to accounts.

From the terminal:

    ms terze anteprima https://github.com/anthropics/skills            # what it contains
    ms terze aggiungi https://github.com/anthropics/skills --percorso skills/canvas-design --verso locale
    ms terze elenco
    ms terze destinazioni canvas-design locale work-api
    ms terze aggiorna                       # all; --forza to replace copies modified here too
    ms terze sincronizza --prova            # then without --prova; --verso <account> for one only
    ms terze rimuovi canvas-design

Safety:
- manage-skill never runs the scripts of third-party skills. It lists them, in the Scripts column and in the preview, so you can check them before using the skill with Claude;
- the secret check runs before every sync;
- ZIPs are extracted only if they contain no dangerous paths, and downloads are limited to 50 MB;
- git clone never asks for credentials: a private repository must be made accessible beforehand, for example with an SSH key.

17. Prompt to recreate a skill
------------------------------

Creates a text to paste into Claude (a new claude.ai chat, Claude Code or another account) that rebuilds the skill with the same structure and the same files. It is useful, for example, to bring a skill into an account where you cannot upload ZIPs, or to have Claude review it.

The prompt contains:
- the instructions for Claude: recreate the skill exactly, without summarizing or improving the text;
- where to install it, in Claude Code or on claude.ai;
- the folder tree;
- every file in a block with its path.

There are two modes:
- complete: all text files, word for word. The skill comes back identical;
- essential: only SKILL.md plus the list of the other files, which Claude writes following the instructions. It is shorter.

Binary files and files that are too large (over 200 KB, or over 600 KB in total) are only listed. The prompt is in the language chosen for the interface.

Safety: lines where the secret check finds keys, tokens or passwords are redacted with a placeholder, and the prompt says how many. No credential ends up in the chat.

- Window: in the Catalog select the skill (and, if you like, a specific copy in the copies panel), then press Prompt…; or Prompt to recreate the skill in the skill details. The preview opens, editable, with the mode choice and the Copy to clipboard and Save as file… buttons.
- Terminal:

    ms prompt my-skill              # print the prompt
    ms prompt my-skill --copia      # copy it to the clipboard (wl-copy, xclip or xsel)
    ms prompt my-skill --essenziale --file ~/prompt.md
    ms prompt other-skill --da claude-ai   # from the claude.ai copy
